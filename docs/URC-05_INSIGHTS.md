# URC-05 streaming insights boundary

The projection validates label, month, country, platform, exact decimal stream count, source system, revision and observation time. It selects newest revisions per period/country/platform/source-kind tuple and sums counts with `BigInt`, returning a decimal string. An ALL-country row is preferred over its component countries only within the same month/platform/source kind; it is never added to those components. A missing selection returns `availability: "awaiting"` and `totalStreams: null`; it does not imply zero streams. Source state distinguishes live, cached and explicitly synthetic data. Synthetic revisions cannot replace observed rows. Mixed synthetic and observed selections are marked mixed and have no combined business total.

The same-origin client reads `/api/labels/{labelId}/reports/streams` through the authenticated BFF with no provider key. It uses no-store caching, strict JSON/UTF-8 parsing, a 2 MB streamed byte limit and a bounded request deadline (default 10 seconds, maximum 30). Scope changes cancel body consumption and discard stale results. Provider diagnostics are replaced with fixed public errors. A 50,000-key bound prevents unbounded revision history; a fresh authenticated app lifetime needs a fresh client.

Only `period`, `country` and `platform` filters are accepted; filters cannot override the requested label, expected source, clock or freshness policy. Every observed source key is checked for rollback and conflicting equal revisions even if its record is currently filtered out. A response can contain historical revisions in arbitrary order; only the newest per key is retained. Identical equal revisions are safe to retry.

`mountStreaming(root, options)` in `src/streaming-view.mjs` exposes `load(labelId, filters)` and `dispose()`. It mounts labeled month/country/platform form controls, semantic source-provenance tables and exact integer formatting, and clears old data synchronously during scope/filter changes. The selected label must come from the authenticated app's current menu; UI filtering never authorizes access. Awaiting data is shown as unavailable, not zero, and mixed demo/observed totals are withheld. Browser/accessibility acceptance remains unverified because an installed Chromium executable was unavailable in this activation.

Coverage includes exact counts, context-override denial, overlapping ALL aggregates, synthetic separation, rollback after filter changes, failure/retry, streamed overflow/deadline and safe semantic rendering.
