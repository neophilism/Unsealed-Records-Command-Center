# URC-04 catalog identity boundary

The catalog projection validates typed owning-label/release/work/track identifiers, release date/title, work relationships, track-level ISRCs, HTTPS artwork hosts on the standard port, and explicit source system/status/revision/time. Known nested work/track label IDs must agree with the requested label. Source status is one of `live`, `cached`, `synthetic`; missing or unknown status is rejected rather than inferred. The source contract is a local proposed boundary and must still be reconciled with the actual Engine contract.

The revision guard rejects late revisions and conflicting equal revisions per label/release/source. The browser client computes a SHA-256 fingerprint of the validated projection so an identical repeated response can be retried safely. Callers using the guard without a fingerprint retain strict duplicate rejection. The guard retains at most 2048 source keys and fails closed if that bound is reached; create a fresh client on a new authenticated app lifetime. Authorized grouping rejects releases outside the supplied label scope.

The same-origin catalog client requests only `/api/labels/{labelId}/reports/catalog`, carries no provider key, requests no-store caching, and discards old in-flight results after a label switch. Each request has a bounded deadline (default 10 seconds, maximum 30), a 1 MB streamed byte limit, strict JSON media type/UTF-8 parsing and body cancellation. Public errors never include raw provider diagnostics.

`mountCatalog(root, options)` in `src/catalog-view.mjs` creates the catalog client and returns `select(labelId)` and `dispose()`. Supply the verified `expectedSource` and approved `artworkHosts`; call `select` only for labels in the authenticated menu. It clears the prior record synchronously during a switch, renders escaped semantic headings/tables with track ISRC/composition, and visibly labels cached observations and synthetic demos. Disposal clears the view and cancels work. This browser UI is not authorization: the BFF must check the current user/label on every request. No token or provider credential is accepted by this mount API.

Run `node --test tests/catalog-*.test.mjs`. The tests cover a valid release, wrong labels, malformed identifiers and ISRC, duplicate or dangling work relations, unsafe artwork, future provenance, late revisions, scope switching, and missing reports.

The committed test imports now resolve the actual `src/` modules. The prior tree failed with `ERR_MODULE_NOT_FOUND` for `tests/catalog-client.mjs` and `tests/catalog.mjs`; do not reproduce earlier passing claims by copying aliases into the tests directory. Additional tests cover streamed overflow/deadline/cancellation, identical/conflicting retries, explicit source state, escaped rendering, immediate clearing and disposal.

Optional browser verification is `node scripts/catalog-browser-smoke.cjs` from the repository root in an approved environment with Playwright and its Chromium executable already installed. It serves only local fixtures, blocks external requests, and checks real DOM rendering, escaped metadata and scope-switch clearing. Browser verification in this activation could not run: Playwright returned `Executable doesn't exist` for its Chromium headless shell. Node tests passing do not establish browser/accessibility acceptance.

This projection does not authenticate the upstream source or the user. The production BFF must verify both before returning a catalog response. The Music Operations Engine catalog contract and live provider data have not been verified; do not label this draft as live integration. ISRC syntax is not rights or ownership proof. The legacy `projectLabelRelease` helper remains for compatibility with earlier draft consumers and should be removed when all callers migrate.
