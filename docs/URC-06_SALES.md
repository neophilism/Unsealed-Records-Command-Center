# URC-06 storefront sales boundary

The normalized event model distinguishes sale, discount, refund and fee events. It keeps amounts as exact decimal strings in currency minor units, selects the highest source revision per source kind/event, rejects duplicate conflicts and over-refunds, and groups order dimensions by source kind, currency, storefront and country. A revision cannot change an event's order, currency, storefront, country or event kind. A zero-priced sale is an observed order, while a refund without a supporting sale fails closed. This is a proposed normalized boundary, not a verified processor or accounting contract.

Gross, discounts, refunds, fees, settled net and pending net remain separate per currency. Empty selections are awaiting data rather than zero revenue. Synthetic and observed IDs, orders and balances are isolated. Mixed results have no combined `currencies` total; `sourceSummaries` provides separate observed/demo currency groups and source observation ranges. A synthetic revision cannot replace an observed event with the same ID. Settled net is a transaction-status view, not a claim of accounting recognition.

The same-origin sales client reads `/api/labels/{labelId}/reports/sales` through the authenticated BFF, carries no provider credential and requests no-store caching. Filters are limited to period/country/storefront; they cannot override trusted label, expected source or clock. Every source event is checked for rollback or conflicting equal revisions across requests before the revision map is updated atomically. The map is bounded to 50,000 keys per client lifetime. Body reads have a 2 MB byte cap, strict JSON/UTF-8 parsing, cancellation and a bounded deadline (default 10 seconds, maximum 30). Public errors omit raw provider diagnostics.

`mountSales(root, options)` in `src/sales-view.mjs` returns `load(labelId, filters)` and `dispose()`. It mounts month/country/storefront controls and semantic tables, clears old data synchronously during a scope switch, and separates observed/demo sections. Supply a verified `currencyDigits` map for every displayed currency; the formatter uses exact BigInt division and never assumes every currency has two fractional digits. Missing currency formatting displays unavailable amounts rather than inventing a scale. Use only labels supplied by the authenticated app's current menu. Neither client filtering nor these projections authorize a user.

No processor, distributor, or Music Operations Engine sales contract has been verified in this repository. Taxes, multi-currency conversion, payout reconciliation and revenue recognition are not implemented. Server-side authentication, provider authorization and signed source evidence remain required before exposing financial data. The legacy `projectStorefrontSale` helper remains for earlier draft consumers.
