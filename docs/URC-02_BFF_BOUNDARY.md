# URC-02 backend-for-frontend trust boundary

The BFF validates RS256 signatures against a server-configured JWK set, exact issuer and audience, a five-minute token lifetime, and a signed per-label grant. It does not accept browser-supplied identity flags or labels. Requests without a matching active grant never reach the engine. Only server-configured report routes are outbound. Redirects and unexpected response labels fail closed. Engine credentials stay in the server process. Large decimal values must be strings in the upstream JSON contract.

Run with Node 20 or newer and `node --test tests/bff-*.test.mjs`. Start with `node src/bff/main.mjs`. Configure BFF_ISSUER, BFF_AUDIENCE, BFF_JWKS_JSON, ENGINE_ORIGIN, ENGINE_TOKEN and BFF_REPORT_ROUTES_JSON on the server. The JWKS must come from the trusted identity issuer and rotate with deployment. Example route configuration: `{"streams":"/v1/labels/{labelId}/reports/streams"}`. Do not enable a route until the upstream Music Operations Engine contract and tenant enforcement are verified. Health is at `/healthz`.

This is an authenticated API boundary, not a complete interactive login flow. Remaining work includes issuer provisioning, current membership/revocation, upstream contract validation, retries/source ordering, frontend integration and deployment smoke tests. Tokens are deliberately short-lived; live revocation needs an issuer or server-side membership check.
